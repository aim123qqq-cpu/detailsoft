# Нативное приложение DetailFlow

Решение владельца от 20.10.2026: телефонное приложение переводится с WebView на нативное. Технология — React Native (Expo, TypeScript). Сейчас делаем Android, iPhone позже: код пишется так, чтобы iOS собрался без переделки, когда появятся Mac или облачная сборка и аккаунт Apple.

## Что меняется и что нет

- Сервер, база и API не меняются. Нативное приложение — ещё один клиент того же API.
- Веб-версия остаётся: компьютер администратора, установка из браузера (в том числе на iPhone), лендинг.
- WebView-оболочка `android/` остаётся, пока нативное приложение не закроет все экраны. Потом она удаляется, а `applicationId` `ru.detailflow.app` и ключ загрузки переходят к нативной сборке, чтобы обновление ставилось поверх.

## Устройство

- `mobile/` — отдельный проект Expo со своим `package.json` (npm). Корневой проект на pnpm его не трогает.
- Общая логика не копируется, а берётся из `src/shared/`: схемы кузовов, правила записи, сборка актов, нормализация телефона и госномера. Metro смотрит в эту папку (`mobile/metro.config.js`). Файлы в `src/shared` остаются без зависимостей от браузера и React DOM.
- Экраны и навигация нативные: стек и нижние вкладки React Navigation через `expo-router`, системные списки, клавиатура, жесты «назад».
- Работа без сети: та же очередь изменений и те же правила (`src/offline/*`), но хранилище — SQLite на устройстве вместо IndexedDB. Для этого `store.ts` получает адаптер хранения.
- Камера и фото — `expo-image-picker`, подпись — рисование на холсте (`react-native-svg`), «Поделиться» — системное меню.
- Адрес сервера задаётся при первом запуске, как в оболочке. Токен сессии — в защищённом хранилище (`expo-secure-store`).

## Этапы

Каждый этап — рабочий APK, который можно ставить. Экраны, которых ещё нет, показывают, что раздел появится в следующей версии, и предлагают открыть его в веб-версии.

1. **Основа:** адрес сервера, вход (код доступа, Telegram/MAX), нижние вкладки как в вебе (одинаковые для всех ролей), список заказов, профиль (выход, удаление аккаунта, сервер, политика).
2. **Работа мастера:** «Мои» заказы, чек-лист, пауза, завершение.
3. **Приёмка:** тип кузова, схема с номерами, замечания, фото с камеры.
4. **Записи и клиенты:** поиск по телефону и госномеру, клиент, автомобиль, выбор услуг и времени, календарь.
5. **Смета, согласование, выдача, акты и подпись.**
6. **Управление:** каталог, команда и роли, график, статистика.
7. **Без сети** на SQLite, затем замена оболочки и публикация в RuStore.

## Статус

- 20.10.2026: этапы 1 и 2 готовы и проверены на эмуляторе Pixel_8 сценарием `tests/android/native-smoke.mjs` (версия 0.4.0). Сборка локально (`scripts/build-mobile.mjs`) и в GitHub Actions (`.github/workflows/mobile.yml` + `scripts/sign-mobile.mjs`).
- 20.10.2026: этап 3 (версия 0.5.0). Приёмка открывается из карточки заказа в статусе «Приёмка» (и до выпуска сметы её можно исправить). Внутри: тип кузова, та же схема с номерами из `src/shared/carLayouts.ts` (нативный SVG), шторка замечания с быстрыми вариантами, тяжестью и фото элемента, салон и прочее, фото общего вида с камеры или из галереи (сжатие до 1280 px, как в вебе), рекомендация клиенту, комментарий. Фото сохраняются сразу, осмотр — кнопкой; уход с несохранёнными изменениями спрашивает подтверждение. Карточка заказа показывает схему с отметками. Заказ из записи пока создаётся в веб-версии (этап 4).
- 20.10.2026: этап 4 (версия 0.6.0).
  - **Вкладка «Записи»:** список (требуют отметки и ближайшие по дням) и режим «По дням» — неделя с количеством записей. Списки обновляются при каждом открытии вкладки.
  - **Карточка записи:** звонок клиенту, состав, перенос на свободное время, отмена, неявка, «Клиент приехал — начать приёмку» (создаёт заказ и открывает осмотр).
  - **Вкладка «Новая»:** канал, поиск по телефону или госномеру, новый клиент, новый автомобиль (из справочника или вручную), услуги с предварительным расчётом, день и свободное время, подтверждение с переходом к приёмке.
  - **Карточка клиента:** контакты, автомобили с кнопкой «Записать», предстоящие записи, заказы.
  - **Пока в веб-версии:** изменение состава записи, обращения (лиды), правка и архив клиента, передача автомобиля.
- 20.10.2026: этап 5 (версия 0.7.0). Весь путь заказа теперь в нативном приложении.
  - **Карточка заказа** показывает следующий шаг по статусу и правам: приёмка → смета → решение клиента → работы → выдача → документы.
  - **Смета:** строки из записи, рекомендации по осмотру с ценой, свои строки; сумму можно поправить. После отказа клиента — новая версия на основе прежней.
  - **Согласование:** способ (лично, по телефону, в мессенджере) и ответственный.
  - **Выдача:** фото до и после работ (результат снимается камерой), чек-лист, кто выдал, комментарий.
  - **Акты приёмки и выдачи:** предпросмотр, ФИО, подпись пальцем (PNG, как в вебе) или без подписи. Просмотр выпущенного акта и PDF через системное меню «Поделиться»; файл называется по номеру акта.
  - **Закрытый заказ:** «Поделиться заказ-нарядом» — текстом, как в вебе.
  - На эмуляторе камера с аппаратной графикой роняла Pixel_8; сценарий гоняется с `-gpu swiftshader_indirect`.
- Версия 0.4.0 подписана ключом загрузки. Отладочная оболочка 0.2.0 была подписана отладочным ключом, поэтому её нужно один раз удалить перед установкой; дальше версии ставятся поверх.

## Проверка

- Логика из `src/shared` уже покрыта тестами сервера и веба.
- Для экранов — сценарии на эмуляторе Android (Pixel_8) с реальным сервером и скриншоты каждого этапа.
- Сборка: `npx expo prebuild` и Gradle, подпись тем же ключом загрузки (`android/keystore.properties`).
