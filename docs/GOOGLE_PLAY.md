# Публикация DetailFlow в Google Play

Пошагово, от регистрации до выхода в продакшен. Сверено с правилами Google Play на 2 ноября 2026 года. Требования меняются: если экран консоли отличается от описанного, ориентируйтесь на смысл шага.

Готовый пакет файлов собирается командой `node scripts/store-packages.mjs` в `artifacts/GooglePlay/` (в git не попадает): AAB, иконка, обложка, скриншоты, тексты и данные для проверки.

## Сколько это займёт

| Этап | Время |
|---|---|
| Регистрация и проверка личности | 1–3 дня |
| Закрытое тестирование: 12 тестировщиков 14 дней подряд | минимум 14 дней |
| Заявка на продакшен и её рассмотрение | до 7 дней |
| Проверка первой версии | 1–7 дней |

Итого реалистично 3–4 недели. Самое долгое — закрытое тестирование, его стоит начать как можно раньше.

## Шаг 0. Что подготовить заранее

1. **Google-аккаунт для разработчика** — лучше отдельный, не личный: например `detailflow.dev@gmail.com`. Он станет владельцем приложения навсегда.
2. **Банковская карта для взноса $25.** Российские карты Google не принимает. Нужна карта иностранного банка на ваше имя (или на имя доверенного человека — тогда аккаунт формально будет его). Взнос разовый.
3. **Паспорт** — для проверки личности.
4. **Телефон** — для подтверждения по SMS.
5. **12 человек с Google-аккаунтами и Android-телефонами** для закрытого тестирования (см. шаг 4). Это обязательно для личных аккаунтов, созданных после 13 ноября 2023 года.

## Шаг 1. Регистрация аккаунта разработчика

1. Откройте [play.google.com/console/signup](https://play.google.com/console/signup) под Google-аккаунтом разработчика.
2. Тип аккаунта — **«Для себя» (Personal)**. Вы самозанятый, организации нет. Аккаунт организации потребовал бы D-U-N-S и юрлицо.
3. Заполните:
   - **Имя разработчика** (показывается в магазине): `DetailFlow`.
   - **Контактное имя и адрес**: Шиганов Никита Сергеевич, адрес как в паспорте.
   - **Email для связи с пользователями**: `detailfow@mail.ru`.
   - **Телефон**: ваш, подтвердите кодом.
   - **Опыт с Android и Google Play**: честно, «нет опыта» не мешает.
4. Оплатите $25.
5. **Проверка личности**: загрузите фото паспорта, имя должно совпадать с платёжным профилем. Проверка 1–3 дня, письмо придёт на почту.

## Шаг 3. Настройка приложения (раздел «Контент приложения»)

Консоль покажет список заданий «Настройте приложение». Ответы на все:

### Политика конфиденциальности
`https://detailflow.ru/privacy/`

### Доступ к приложению
Выберите **«Весь функционал или его часть ограничен»** → «Добавить инструкции»:
- **Название**: Тестовый центр
- **Имя пользователя**: не требуется
- **Пароль**: код доступа из `artifacts/GooglePlay/5-доступ-для-проверки.txt` (в git его нет; новый код можно выпустить, см. [STORE.md](STORE.md), «Данные для проверки»)
- **Инструкция**: текст из того же файла — на экране входа нажать «Войти по коду доступа», ввести код в поле «Код доступа сотрудника» и нажать «Войти по коду», затем принять соглашение и согласие.

### Реклама
**Нет, в приложении нет рекламы.**

### Возрастные ограничения (анкета IARC)
- Email: `detailfow@mail.ru`
- Категория: **«Все остальные типы приложений»** (не игра, не соцсеть).
- Все вопросы о насилии, сексуальном контенте, языке, наркотиках, азартных играх: **Нет**.
- Взаимодействие пользователей: **Да** — сотрудники одного центра видят общие данные (записи, заказы). Обмена сообщениями и публикации контента для всех нет.
- Покупки в приложении: **Нет**. Передача местоположения: **Нет**.

Ожидаемый рейтинг: 3+ / PEGI 3.

### Целевая аудитория
**18 лет и старше** — это рабочий инструмент для бизнеса. Приложение не для детей.

### Новостное приложение
**Нет.**

### Приложения для госорганов, финансовые функции, здоровье
**Нет** по всем пунктам. Учёт сумм в заказах — не финансовая услуга: денег приложение не принимает и не переводит.

### Безопасность данных (Data safety)

**Общие вопросы:**
- Собирает или передаёт ли приложение данные пользователей: **Да**.
- Все данные шифруются при передаче: **Да** (HTTPS).
- Пользователь может запросить удаление: **Да**, ссылка на удаление аккаунта: `https://detailflow.ru/privacy/#delete`.

**Какие данные собираются** (все — «собираются», ни одно — «передаётся третьим лицам»; хостинг не считается передачей):

| Тип в анкете | Что это в DetailFlow | Цель | Обязательно |
|---|---|---|---|
| Личная информация → Имя | имя сотрудника; имена клиентов центра, которые вносит сотрудник | Функции приложения; Управление аккаунтом | Да |
| Личная информация → Адрес эл. почты | email для входа | Управление аккаунтом | Нет (можно входить через мессенджер или по коду) |
| Личная информация → Номер телефона | телефоны клиентов центра | Функции приложения | Да |
| Личная информация → Другая информация | госномер, марка и цвет автомобиля клиента; подпись клиента в акте | Функции приложения | Да |
| Фото и видео → Фото | фото автомобиля при приёмке и выдаче | Функции приложения | Нет |
| Действия в приложении → Другие действия | кто и что сделал в заказе (журнал) | Функции приложения | Да |

Для каждого типа:
- **Обрабатываются эфемерно:** Нет.
- **Сбор обязателен:** как в таблице.
- **Передача третьим лицам:** Нет.

Не собираются: местоположение, финансовая информация, контакты телефона, сообщения, аудио, файлы, календарь, данные о здоровье, идентификаторы устройства, данные о сбоях и аналитика.

### Удаление аккаунта
Ссылка: `https://detailflow.ru/privacy/#delete`. В приложении путь — «Профиль → Удалить аккаунт».

## Шаг 4. Закрытое тестирование: 12 человек, 14 дней

Без этого шага кнопка «Опубликовать в продакшене» недоступна.

1. **Тестирование → Закрытое тестирование → «Создать трек»** (или используйте трек Alpha).
2. **Тестировщики** → «Создать список адресов» → добавьте Gmail-адреса минимум **12** человек. Лучше 15–20, с запасом: если кто-то выйдет из теста, счёт его дней обнулится.
3. **Страны**: Россия (и другие, где будут тестировщики).
4. **Создать выпуск** → загрузите `artifacts/GooglePlay/0-DetailFlow-1.1.0.aab`.
   - При первой загрузке консоль предложит **подписание приложений Google Play** — согласитесь (см. «Подпись» ниже).
   - Название выпуска: `1.1.0 (11)`. Примечания: текст «Что нового» из `3-тексты-карточки.txt`.
5. **Отправить на проверку.** Первая проверка — от нескольких часов до нескольких дней.
6. После одобрения скопируйте **ссылку для присоединения** (Тестировщики → «Как тестировщики присоединяются») и разошлите людям. Каждый должен:
   - открыть ссылку на телефоне под своим Gmail,
   - нажать «Стать тестировщиком»,
   - установить DetailFlow из Google Play по ссылке,
   - **не выходить из теста 14 дней подряд** и хотя бы иногда открывать приложение.

   Тестировщики могут работать в тестовом центре по коду доступа или создать свой центр.
7. Через 14 дней на главной консоли станет активна кнопка **«Подать заявку на доступ к продакшену»**. Google спросит:
   - как вы набирали тестировщиков (знакомые владельцы и сотрудники детейлинг-центров);
   - какие отзывы получили и что исправили;
   - готово ли приложение (да, с примерами функций).

   Отвечайте подробно и по-русски или по-английски. Ответ — до 7 дней.

## Шаг 6. Продакшен

1. **Продакшен → Создать выпуск** → «Добавить из библиотеки» (тот же AAB, что прошёл тест) или загрузите новый с бо́льшим `versionCode`.

## Подпись: важно понимать

- AAB подписан **ключом загрузки** (`C:\Users\USER\.detailflow\detailflow-upload.jks`). Google проверяет им, что выпуск от вас.
- С **подписанием приложений Google Play** Google хранит у себя отдельный **ключ приложения** и подписывает им то, что ставят пользователи. Это стандарт и обязательно для AAB.
- Из-за этого версия из Google Play и версия из RuStore/AppGallery будут подписаны разными ключами. Поставить «поверх» версию из другого магазина нельзя — нужно удалить и установить заново. Данные на сервере при этом не теряются.
- Если важно, чтобы подпись везде была одна, при первом выпуске выберите **«Использовать другой ключ подписи» → «Экспортировать и загрузить ключ из Java KeyStore»** и следуйте инструкции консоли (утилита PEPK). Тогда Google будет подписывать вашим же ключом.
- Ключ загрузки и `keystore.properties` храните в резервной копии. Потеря ключа загрузки исправима через поддержку Google, но займёт время.

## Обновления

1. Увеличьте `versionCode` в `mobile/app.json` (сейчас 11), при заметных изменениях и `version`.
2. `node scripts/build-mobile.mjs aab` → `node scripts/store-packages.mjs`.
3. Продакшен → «Создать выпуск» → загрузить новый AAB, написать «Что нового» → на проверку.

## Частые причины отказа и как их избежать

| Причина | Как у нас |
|---|---|
| Проверяющий не смог войти | В «Доступе к приложению» есть код тестового центра. Проверьте его перед отправкой. |
| Нет политики или удаления аккаунта | Есть: `/privacy/` и `/privacy/#delete`, удаление в «Профиле». |
| Данные в Data safety не совпадают с приложением | Заполните строго по таблице выше. |
| Лишние разрешения | Только камера и чтение фото на Android 12 и ниже; лишние убраны в `mobile/app.json`. |
| Уровень API ниже требуемого | Сборка под API 36, это требование с 31.08.2026. |
