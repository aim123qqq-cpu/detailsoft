# API — итерации 1–3

Все маршруты `/api/*`, кроме `/api/health`, требуют `Authorization: Bearer <session-token>`. Tenant извлекается из серверной сессии; переданный клиентом `x-tenant-id` не определяет область данных.

Ошибки имеют единую форму:

```json
{"error":{"code":"validation_error","message":"Проверьте данные"}}
```

## Реализованные маршруты

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/api/customers?phone=` | Частичный поиск клиентов по нормализованному телефону; всегда возвращает `{ items: [] }` |
| `POST` | `/api/customers` | Создание клиента из `{ name, phone }` с сохранением введённого отображаемого номера |
| `GET` | `/api/customers/{id}/vehicles?includeArchived=false` | Автомобили клиента по активным временным связям |
| `GET` | `/api/vehicles?plate=` | Частичный поиск по нормализованному госномеру в текущем tenant |
| `GET` | `/api/vehicle-catalog/variants?q=` | Варианты `марка → модель → поколение → кузов → системный класс` |
| `POST` | `/api/vehicles` | Атомарное создание автомобиля и `CustomerVehicle`; возможный дубль возвращает `409 possible_duplicate` |
| `PATCH` | `/api/vehicles/{id}` | Изменение статуса на `active`, `inactive` или `sold` без удаления истории |
| `GET` | `/api/tenants/current/services?vehicleId=` | Каталог текущего центра с ценами и длительностью для tenant-класса автомобиля |
| `POST` | `/api/bookings/quote-preview` | Серверный предварительный расчёт услуг и пакетов с исключением повторной оплаты операций |
| `GET` | `/api/bookings/availability?date=&durationMinutes=` | Доступность слотов по одновременной вместимости центра без обязательных боксов |
| `POST` | `/api/bookings` | Создание записи и неизменяемого снимка рассчитанных строк; требует `Idempotency-Key` |
| `GET` | `/api/bookings/{id}` | Чтение созданной записи в пределах tenant |
| `POST` | `/api/orders` | Создание или безопасный повтор создания заказа из `{ bookingId }` |
| `PUT` | `/api/orders/{id}/intake` | Снимок состояния, дефекты и рекомендации; перевод в `ESTIMATE_DRAFT` |
| `POST` | `/api/orders/{id}/estimates` | Выпуск следующей неизменяемой версии сметы с серверным итогом |
| `POST` | `/api/orders/{id}/estimate-approvals` | Решение по актуальной версии с методом, источником и ответственным |
| `PUT` | `/api/orders/{id}/assignment` | Назначение мастера; роль `admin` |
| `POST` | `/api/orders/{id}/work/start` | Старт работ и снимок операций согласованной сметы |
| `PATCH` | `/api/orders/{id}/work/operations/{operationId}` | Статус операции мастера: `PENDING`, `DONE`, `BLOCKED` |
| `POST` | `/api/orders/{id}/work/pause` | Пауза с обязательной причиной |
| `POST` | `/api/orders/{id}/work/resume` | Возобновление работ |
| `POST` | `/api/orders/{id}/work/complete` | Передача в QC только после всех выполненных операций |
| `POST` | `/api/orders/{id}/qc` | `PASSED` переводит в `READY`; `REWORK` создаёт обязательную доработку |
| `POST` | `/api/orders/{id}/payments` | Частичная или полная оплата; требует `Idempotency-Key` |
| `POST` | `/api/orders/{id}/handover` | Выдача автомобиля и перевод полностью оплаченного заказа в `CLOSED` |
| `GET` | `/api/orders/{id}` | Полный заказ: приёмка, версии сметы, решение и журнал аудита |

Списковые маршруты ограничены десятью результатами. Параметры SQL передаются через prepared statements. Тело JSON ограничено 64 КиБ. Денежные значения API передаются целым числом в минимальных единицах (`amountMinor`).

## Контракт предварительного расчёта

`quote-preview` принимает `vehicleId` и массив `selections` с элементами `{ type: "service" | "package", id }`. Цена услуги складывается из её операций для tenant-класса автомобиля. Сначала учитываются операции пакетов; совпадающие операции отдельных услуг возвращаются в `excludedOperations` и не прибавляются повторно.

Ответ содержит:

- `preliminary: true`;
- `lines` со снимком операций и режимом цены;
- `totalAmountMinor` и `totalDurationMinutes`;
- `warnings` для пересечений пакета и цен, уточняемых после осмотра.

`POST /api/bookings` повторяет расчёт на сервере и не доверяет сумме из браузера. `resourceId` может быть `null`: наличие выделенного бокса не является условием создания записи. Повтор идентичного запроса с тем же `Idempotency-Key` возвращает ранее созданную запись; другой payload с тем же ключом получает `409 idempotency_conflict`.

Пересекающиеся отдельная услуга и пакет разрешены: оплачиваемые операции услуги уменьшаются на операции пакета. Два пакета с общими операциями возвращают `409 package_overlap`, поскольку без отдельной декомпозиции цены корректно распределить скидку невозможно. Занятый сверх вместимости слот возвращает `409 slot_unavailable`.

## Контракт заказа и сметы

`POST /api/orders` принимает подтверждённый `bookingId`. Одна запись порождает не более одного заказа в tenant: повтор возвращает тот же заказ с `200`. Новый заказ начинается в `INTAKE`.

`PUT /api/orders/{id}/intake` принимает `conditionSummary`, массив `findings` (`zone`, `severity`, `note`) и массив `recommendations` (`title`, `reason`, `priority`). После сохранения заказ переходит в `ESTIMATE_DRAFT`, а событие `INTAKE_COMPLETED` попадает в аудит.

Каждый `POST /api/orders/{id}/estimates` создаёт новый снимок строк и вычисляет итог на сервере. Старые версии не обновляются. Согласовать можно только `currentEstimateVersionId`; устаревшая версия возвращает `409 stale_estimate`. Решение требует `decision`, `method`, `source` и `responsible`. После `APPROVED` приёмку нельзя молча переписать (`409 invalid_order_state`).

При старте работ операции копируются только из согласованной версии сметы: мастер не может добавить платную работу через производственный API. Незавершённая операция возвращает `409 operations_incomplete`. Провал QC создаёт операцию `qc_rework` с нулевой стоимостью, возвращает заказ в `IN_PROGRESS` и фиксируется в аудите. Доступ к назначению, работе и QC проверяется по ролям серверной сессии.

Платёж принимает целое `amountMinor`, `method` (`cash`, `card`, `transfer`) и `responsible`. Повтор запроса с тем же `Idempotency-Key` не создаёт второй платёж; переплата возвращает `409 payment_exceeds_balance`. Выдача разрешена только из `READY` при нулевом остатке, после чего заказ получает статус `CLOSED`, а события `PAYMENT_RECORDED` и `ORDER_CLOSED` сохраняются в аудите.

## Отличия от предложений исходной спецификации

- Пути основных ресурсов совпадают с предложенными, но отдельные маршруты создания/закрытия `CustomerVehicle` пока не опубликованы: в этом инкременте связь создаётся атомарно вместе с автомобилем.
- Смена владельца с аудитом, ручное добавление отсутствующей модели и редактирование tenant-класса остаются следующими срезами итерации 1.
- Редактирование/перенос/отмена записи и календарная проверка загрузки относятся к следующему срезу Booking.
- Фото приёмки и выдачи пока представлены интерактивными слотами без бинарного хранилища. Электронная подпись, эквайринг и закрывающие документы остаются следующими срезами итерации 3.
- Каталог сейчас заполнен демонстрационными данными одного центра; административный редактор каталога ещё не реализован.
- SQLite и bearer-токены — локальная реализация прототипа; production-хранилище и существующая auth-система в исходном пустом репозитории отсутствовали.
