# Развёртывание и обслуживание

Инструкция для того, кто ставит и обновляет DetailFlow: на компьютере в центре или на облачном сервере.

## Как устроено

- Один процесс Node.js 24 (`server/index.mjs`) отдаёт интерфейс из `dist/` и API.
- Все данные лежат в одном файле SQLite `data/detailflow.db`. Миграции применяются сами при каждом запуске и только добавляют таблицы.
- Боты Telegram и MAX работают через long polling: серверу нужен только исходящий интернет, входящие вебхуки не нужны.
- **Запускайте один экземпляр на одну базу.** Два процесса с одним токеном бота будут мешать друг другу получать сообщения, а лимит попыток входа хранится в памяти процесса.

## Переменные окружения

Задаются в файле `.env` рядом с `package.json` (в git не попадает, образец — `.env.example`) или в окружении службы.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `4173` | Порт HTTP |
| `HOST` | `127.0.0.1` | Адрес прослушивания. За reverse proxy на той же машине оставьте по умолчанию; `0.0.0.0` открывает порт в сеть |
| `DATABASE_PATH` | `data/detailflow.db` | Файл базы |
| `TELEGRAM_BOT_TOKEN`, `MAX_BOT_TOKEN` | — | Токены ботов для входа сотрудников |
| `DEMO_AUTH` | `true` | `false` убирает демо-доступ и кнопку «Продолжить в демо-режиме» |
| `SEED_DEMO` | `true` | `false` не создаёт демо-центр с примерами данных |
| `BACKUP_DIR` | `data/backups` | Папка резервных копий |
| `BACKUP_KEEP` | `14` | Сколько копий хранить |
| `BACKUP_INTERVAL_HOURS` | `24` | Период автоматической копии; `0` выключает таймер |
| `ENABLE_QC` | — | `true` временно возвращает этап QC (см. README) |

## Первый запуск в рабочем режиме

```bash
pnpm install --frozen-lockfile
pnpm build
```

В `.env`:

```
TELEGRAM_BOT_TOKEN=<токен от @BotFather>
DEMO_AUTH=false
SEED_DEMO=false
```

Центры создают сами владельцы: на экране входа (в вебе и в приложении) — «Создать свой центр», подтверждение в Telegram или MAX, название центра и своё имя. Человек становится владельцем и дальше приглашает команду сам. С одного аккаунта мессенджера можно создать до 5 центров (`CENTERS_PER_ACCOUNT` в `server/auth-repository.mjs`).

Центр можно создать и с консоли сервера — например, если владелец потерял доступ. Запустите сервер (`pnpm start`) и, не останавливая его, выполните:

```bash
pnpm setup:owner -- --center "Название центра" --owner "Имя Фамилия"
```

Команда напечатает ссылку на бота. Владелец открывает её, нажимает «Старт» и после этого входит в DetailFlow через мессенджер. Приглашение действует сутки и срабатывает один раз; если оно истекло, запустите команду с `--tenant <id>` из её вывода. Остальных сотрудников владелец приглашает сам: «Профиль → Команда».

Уже работающую установку переключать не обязательно: `DEMO_AUTH=false` и `SEED_DEMO=false` ничего не удаляют. Демо-центр просто перестаёт быть доступным без привязанного мессенджера.

## Проверка, что всё работает

```bash
curl http://127.0.0.1:4173/api/health   # {"status":"ok"} — процесс жив
curl http://127.0.0.1:4173/api/ready    # {"status":"ready","database":"ok","messengers":{"telegram":"ready"}}
```

`/api/ready` возвращает `503`, если база не отвечает. Бот в состоянии `unavailable` (неверный токен, нет интернета) на готовность не влияет: сотрудники, уже вошедшие в систему, продолжают работать. Этот адрес подходит для мониторинга (например, UptimeRobot) и проверки балансировщика.

## Обновление

```bash
git pull
pnpm install --frozen-lockfile
pnpm build
# перезапустить службу (см. ниже) или pnpm start
```

При запуске сервер сам сохраняет копию базы до применения миграций: `data/backups/detailflow-<дата>-startup.db`. Остановка по `Ctrl+C`, `systemctl stop` или `docker stop` штатная: сервер завершает текущие запросы, останавливает ботов и закрывает базу. Если что-то зависло, через 10 секунд процесс завершится принудительно.

## Откат

1. Остановите сервер.
2. Верните код: `git checkout <предыдущий коммит>`, затем `pnpm install --frozen-lockfile` и `pnpm build`.
3. Обычно базу возвращать не нужно: миграции только добавляют таблицы, и старый код их просто не использует. Если данные испорчены, восстановите копию, снятую при запуске новой версии:

   ```bash
   pnpm backup -- --list
   pnpm restore -- data/backups/detailflow-<дата>-startup.db
   ```

   Текущая база перед заменой сохранится в `…-before-restore.db`.

## Облачный сервер в России: установка одной командой

Рабочий сервер DetailFlow — облачный сервер в Timeweb Cloud (данные клиентов центров по 152-ФЗ хранятся в России) с собственным доменом и HTTPS. Скрипты подходят для любой машины с Ubuntu 24.04 (Yandex Cloud, Selectel и т. п.).

1. **Сервер** (Timeweb Cloud → «Облачные серверы» → «Создать»):
   - ОС: Ubuntu 24.04;
   - регион в России (Москва или Санкт-Петербург);
   - конфигурация: 1–2 vCPU, 2 ГБ RAM, диск NVMe от 20 ГБ;
   - «Публичный IPv4-адрес»: создать новый (адрес постоянный, оплачивается отдельно);
   - «Авторизация»: добавить SSH-ключ — содержимое `~/.ssh/detailflow_yc.pub` с компьютера, откуда идёт управление, — и выключить «Доступ по SSH через root-пароль»;
   - пользователь — `root` (так у Timeweb по умолчанию; вход только по ключу).
2. **Домен:** A-запись на IPv4 сервера.
3. **Описание сервера** на компьютере управления — `~/.detailflow/server.json` (вне репозитория):
   ```json
   { "host": "<IP>", "user": "root", "domain": "<домен>" }
   ```
4. **Установка:** `node scripts/deploy.mjs setup` — ставит Node.js 24, pnpm, Caddy (сертификат HTTPS сам), пользователя службы `detailflow`, код в `/opt/detailflow`, службу systemd и файрвол (`deploy/setup.sh`). Повторный запуск безопасен.
5. **Перенос данных и токенов ботов** с компьютера: остановите локальный сервер, затем `node scripts/deploy.mjs move-data`. Берётся согласованная копия базы; на сервере прежняя база сохраняется рядом; из локального `.env` переносятся только строки `TELEGRAM_BOT_TOKEN` и `MAX_BOT_TOKEN`.
6. **Обновление:** `node scripts/deploy.mjs` — подтягивает `main`, собирает (при ошибке сборки возвращается к прежней версии) и перезапускает службу; затем проверяет `https://<домен>/api/ready`. Состояние и журнал: `node scripts/deploy.mjs status`.

На сервере `.env` создаётся с `DEMO_AUTH=false`, `SEED_DEMO=false` и копией базы каждые 6 часов (28 копий).

### Telegram из российского дата-центра

Если сервер не достаёт до `api.telegram.org` (в `/api/ready` — `"telegram":"unavailable"`, в журнале — `fetch failed`), Telegram можно пустить через VPN владельца, остальной трафик сервера идёт напрямую. На сервере от root:

```bash
node /opt/detailflow/deploy/telegram-proxy.mjs 'ссылка на подписку VPN'
```

Скрипт ставит sing-box, перебирает серверы из подписки, пока Telegram не ответит, запускает локальный прокси `127.0.0.1:2080` (через VPN — только домены Telegram) и подключает его к службе DetailFlow (`/etc/systemd/system/detailflow.service.d/telegram-proxy.conf`). Ключи хранятся в `/etc/sing-box` (только root) и не выводятся. После перевыпуска ссылки у VPN-сервиса запустите скрипт ещё раз с новой ссылкой.

## Облачный сервер (Linux)

Кнопке «Поделиться» и буферу обмена на телефонах нужен HTTPS. Проще всего поставить перед DetailFlow [Caddy](https://caddyserver.com/): он сам получает и продлевает сертификат.

`/etc/caddy/Caddyfile`:

```
crm.example.ru {
	reverse_proxy 127.0.0.1:4173
}
```

Служба `/etc/systemd/system/detailflow.service`:

```ini
[Unit]
Description=DetailFlow
After=network-online.target
Wants=network-online.target

[Service]
User=detailflow
WorkingDirectory=/opt/detailflow
ExecStart=/usr/bin/node --env-file-if-exists=.env server/index.mjs
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now detailflow
journalctl -u detailflow -f      # журнал
```

`.env` должен быть доступен только пользователю службы: `chmod 600 /opt/detailflow/.env`.

## Компьютер в центре (Windows)

Чтобы сервер запускался вместе с компьютером, создайте задачу в «Планировщике заданий»: триггер «При входе в систему», действие — программа `node`, аргументы `--env-file-if-exists=.env server/index.mjs`, рабочая папка — папка проекта. Без HTTPS «Поделиться» работает только на этом компьютере (`localhost`); с телефонов по адресу `http://192.168…` текст сметы открывается для ручного копирования.

## Резервные копии вне машины

Автоматические копии лежат на том же диске, что и база. Регулярно переносите папку `data/backups/` на другой носитель: облачный диск, NAS или хранилище S3 у хостинга. Копию можно снимать и переносить во время работы сервера. Восстановление описано в README, раздел «Резервные копии».

## Автоматическая проверка (CI)

На каждый push в `main` и на pull request GitHub Actions (`.github/workflows/ci.yml`) собирает проект и запускает все тесты, включая браузерные Chromium E2E на 390 × 844. Скриншоты прогона сохраняются в артефакте `e2e-screenshots` на 7 дней. Красный статус в репозитории означает, что обновлять рабочую установку этим коммитом нельзя.
